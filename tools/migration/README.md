# 迁移工具规划契约

本目录目前只有说明文档，迁移工具**尚未实现**。没有可运行 CLI、导出程序、解析器、导入适配器或数据同步服务。本轮不安装依赖、不构建项目、不导出或写入真实业务数据，也不执行 O2OA 原生配置导入。

迁移规则以[迁移策略](../../docs/migration/01-migration-strategy.md)为准。相关文档为[对象盘点](../../docs/migration/object-inventory.json)、[字段映射示例](../../docs/migration/field-mapping.sample.json)、[需求基线](../../docs/requirements/01-scope-and-requirements.md)、[业务流程](../../docs/requirements/02-business-processes.md)、[待确认事项](../../docs/requirements/03-open-questions.md)及[文档导航](../../docs/README.md)。

两份 JSON 是本项目自己的元数据文档格式，不是源系统已导出的 schema，也不是 O2OA 原生可直接导入配置。目标逻辑字段仍需绑定到经过验证的应用、表单及写入接口；不能据此推导数据库表并直接写库。

## 未来实现的阶段与输入输出

下表描述未来能力契约，不是已存在的命令名称或 API。

| 阶段 | 输入 | 输出与必要行为 |
| --- | --- | --- |
| 包登记与只读检查 | 原始包、来源系统／租户、导出条件、截止时间及批次号 | 原文件清单、大小、SHA-256、格式与缺口报告；不修改原件，不访问目标写接口 |
| 样本脱敏 | 原始副本、明确的脱敏规则 | 人工替换的样本、边界案例及关系一致性报告；真实值与替换字典不进入 Git |
| 解析及映射预检 | 已核对格式的包、完整对象目录、版本化映射规则 | 规范化中间数据、必填／枚举／精度错误、来源唯一键、未解决关联；不能把未知值默认为有效 |
| 目标适配预检 | 测试环境能力、目标绑定、权限及隔离规则 | 适配能力报告、版本与冲突策略；验证通知、审批、付款及过账副作用隔离 |
| 分批导入及关联回填 | 通过预检的批次、目标快照、新旧 ID 台账 | 逐记录结果、目标 ID、内容摘要、回填状态与可重试失败清单；幂等并可续跑 |
| 附件和历史轨迹归档 | 受控文件、索引、摘要及来源轨迹 | 目标引用、完整性／权限报告、缺失清单和历史来源标记；不伪造新引擎运行日志 |
| 核对与切换检查 | 同一范围的源基线、目标读回、批次台账 | 按公司／对象／状态／币种的数量和金额差异、孤立关系、附件差异及在途处置结果 |
| 批次恢复 | 目标快照、写入台账、副作用和切换后新增业务清单 | 可逆范围报告与恢复结果；保护非本批数据，不用恢复快照撤销真实付款 |

## 批次记录的最小要求

每批需要记录来源、批次 ID、导出范围和截止时间、源文件摘要、解析及规则版本、目标环境标识、操作人、开始／结束时间、源行标识、幂等键、目标标识、源内容摘要、写入／回填／核对状态及错误原因。实际环境地址、访问凭证、人员信息和真实业务 ID 只在忽略目录及受控配置中保存。

幂等键至少区分来源系统、源租户、源对象和稳定源记录 ID。暂未取得稳定 ID 时不能开始正式导入。日期与金额规则从实际样本确认；金额核对使用确定的十进制精度，日期值和时间戳不混用。公司归属与跨公司共享权限分开校验。

所有异常必须能归属到批次和源记录。预检、写入、关系回填、附件和验收状态分别记录；部分失败不能返回“全部成功”。重试沿用来源标识和检查点，不重新生成重复业务或重复附件。发现目标人工修改时停留在冲突状态，不能静默覆盖。

## 存储及仓库边界

实际文件统一放在相对于工程根目录的 `.local/migration/<batch-id>/` 下，分别使用 `raw/`、`manifest/`、`samples/`、`staging/`、`id-map/`、`reports/`、`logs/` 和 `backup/`。原始包登记摘要后只读，处理副本可重建，批次结果不得覆盖其他批次。完整目录约定见迁移策略。

即使仓库默认私有，真实导出、附件、日志、凭证、令牌及新旧 ID 映射也不提交版本库，不进入公开 fork 或上游仓库。文档目录只保留元数据、说明和合成示例；日志含有真实标识时仍属于内部数据，不能直接复制到问题单或提交记录。

## 开始实现前需要解决的事项

- 获得可核对的实际导出样本，确认全对象／按对象入口的范围、格式、限制和字段列名。目前仅观察到 UI 入口，实际导出未执行。
- 补齐对象、字段、关联、枚举、源必填约束及稳定源 ID，明确附件和审批轨迹的获取方式。
- 确定目标 O2OA 应用及存储绑定、支持的写入接口、鉴权方式、副作用隔离和恢复能力。当前模板没有提供可直接导入的 O2OA 配置。
- 明确在途流程切换、公司权限、冲突处理、迁移验收负责人和回滚边界。
- 单独确认正式会计账启用日期、期初余额和历史补账范围。业务台账迁移不能自动推导为完整会计核算。

只有上述证据及决策具备后，才依据工程规则拆分工具实现和验证任务；本说明不表示这些能力已经完成。
