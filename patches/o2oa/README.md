# 上游修改登记

当前尚无本公司业务改造补丁。保留 O2OA 原目录和许可证，优先使用配置及扩展能力。

确需修改平台源码时，在准确的源码位置修改，并登记：

- 变更编号、关联需求及原因。
- 来源版本、修改文件、影响的构建及运行能力。
- 可采用的扩展方式及本次必须修改平台的依据。
- 验证范围、结果和未覆盖项。
- 后续上游升级时如何保留、重放或删除这项修改。

常规实现不需要额外用户审批；真实业务口径或已确认范围发生变化时再澄清。登记目录不应复制整份上游源码或保存生产数据。

参见 [开发约束](../../AGENTS.md) 与 [目录规范](../../docs/architecture/01-repository-and-directories.md)。
