# Web v0.1 实现与验证

日期：2026-10-24，Asia/Shanghai。用户要求：先做 Web、模块化，第一版运行与测试通过后结束本轮。数据库暂定 MariaDB。

## 本版实现

- 独立 Vue 3 + TypeScript + Vite 工程，依赖与锁文件均在 `apps/oa-web/`。
- 平台连接、账号密码登录、当前身份与退出、会话失效处理；尊重 O2OA RSA 和双因素配置。
- 工作台、当前用户待办／已办、服务器搜索及分页、详情抽屉、原生表单入口和窄屏导航。
- 页面、复用组件、应用状态、API 契约、HTTP、配置与人工示例分开维护。
- 默认真实模式；人工演示必须主动进入，不能执行审批、付款或记账。
- 隔离平台及 MariaDB 的只读诊断工具；平台源码、许可证和现有数据库未修改。

运行与模块说明见 [Web README](../../apps/oa-web/README.md)，技术决定见 [ADR 0002](../architecture/adr/0002-web-foundation.md)。本版服务地址为 `http://127.0.0.1:5173`，仅本机监听。

测试响应与演示均为明确的合成资料，不使用真实公司账号、业务记录或数据库。截图保存在忽略目录 `.local/verification/web-v0.1/dashboard.png`，不作为真实业务数据或权限验证证据。

代码审查发现并修复了跨账号会话竞态：旧请求可能在退出并登录其他账号后覆盖或清空新 token。HTTP 层现按会话版本取消旧请求，拒绝旧响应更新身份；数据请求忽略 Cookie，身份接口仍使用平台机制。对应正常、迟到 token、迟到 401 和退出失败场景已纳入契约测试。

此处仅表示 Web 第一版技术检查通过。原改造方案的平台接入阶段仍未退出；并行形成的员工界面与适配器没有关闭后续真实流程、权限和数据库联调门槛。本轮按用户要求收在此版本，不继续扩展业务模块。

## 真实联调缺口

当前机器没有可用的 O2OA Java 运行环境和已构建平台产物，Docker 引擎未启动；MariaDB 服务启动尝试被 Windows 服务控制权限拒绝。未建立真实平台或数据库连接，详见 [实测报告](platform-runtime.md)。

因此本版不宣称以下事项通过：原生动态表单和附件完整执行、真实审批、公司隔离、原付款流程全链路、MariaDB JDBC 与事务、正式会计及历史迁移。当前已办仅为个人已办记录，不等同整条流程完成。

继续平台联调时先解决环境和服务权限，使用独立测试库及测试账号，按原 [改造阶段](../architecture/02-o2oa-adaptation-plan.md#5-分阶段推进与验收门槛) 和 [业务验收计划](01-acceptance-plan.md) 逐项记录。未验证项保留开放，不通过默认值或人工演示关闭。
