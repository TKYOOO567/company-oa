## 本轮修改

用户指出原登录页同时展示业务侧栏，点击菜单却回到登录内容，基本操作缺少入口。本轮先完成员工旅程图，再按进入、发起与续填、办理、追踪四条路径完善前端。

未登录时使用独立登录壳，只显示连接、登录和恢复操作；会话有效时进入工作台。登录后导航围绕工作台、发起申请、待我处理、我发起的、草稿箱、我的已办和账号设置。移除了客户、财务等看似可以进入但尚未交付的侧栏项；建设说明归入应用页并标明真实状态。

工作台的统计卡分别进入对应列表，快速发起与完整目录使用服务端允许的流程。创建申请前加载当前账号可用的发起身份，明确输入标题并点击创建；创建中阻止重复点击。表单入口指向创建结果中的草稿或工作，不是通用平台首页。

## 列表与操作含义

| 入口     | 数据与含义                           | 实际操作                                           |
| -------- | ------------------------------------ | -------------------------------------------------- |
| 待我处理 | 当前账号的待办任务，排除拟稿任务     | 搜索、分页、摘要、流转记录及对应动态表单办理       |
| 草稿箱   | 当前账号尚未提交的草稿，独立分页查询 | 读取草稿摘要，以草稿标识打开动态表单继续填写和保存 |
| 我发起的 | 平台创建者追踪记录，草稿不混入此列表 | 查看已提交申请、当前节点、处理人和真实流程终态     |
| 我的已办 | 当前账号本人的已办任务               | 查看个人处理记录；同时区分流程仍流转或已结束       |

四类列表各自使用对应接口，搜索和切换分类重置分页，不将同一份待办换标签展示，也不把草稿和追踪记录拼接成未经平台分页的结果。公司和金额只显示已经返回的业务映射，不根据部门或流程名称猜测。

详情提供可重试的摘要与流转记录。完整字段、动态规则、保存和实际办理路由由 O2OA MWF 运行页承接；新 Web 主操作使用“填写申请表单”“处理申请”“查看申请表单”等员工用语。打开链接不会自动提交申请、选择“同意”或执行会计动作。

## 返回、失败与身份保护

| 情况                             | 当前行为                                                                                     |
| -------------------------------- | -------------------------------------------------------------------------------------------- |
| 表单打开后返回                   | 重新获得焦点或页面恢复可见时刷新列表与仍有效的详情；中途返回不结束跟踪，后续再次返回仍会刷新 |
| 完成操作后手动确认               | 点击“已完成操作，刷新”，成功刷新后结束本次跟踪；刷新失败仍保留重试入口                       |
| 原事项不在当前列表               | 关闭过期详情，避免保留已经提交的草稿入口或已经办理的旧任务操作                               |
| 403 无权限                       | 保留会话，显示受限错误；不循环要求重新登录                                                   |
| 401 会话失效                     | 清空当前身份、列表、草稿、摘要及计数，回到独立登录页                                         |
| 身份切换与迟到响应               | HTTP 会话版本和工作区请求版本使旧结果失效，旧账号响应不能覆盖新账号 token 或记录             |
| 创建结果不确定                   | 显示待核对状态，禁止在当前对话框重发；提示先核对草稿箱和我发起的，不自动重放写请求           |
| 无流程、无身份、无记录或请求失败 | 分开显示有意义的空态或错误，提供刷新、重试、改筛选或联系管理员的下一步                       |

发起、列表、详情和表单权限依赖平台服务端。前端状态、隐藏入口或身份选择框都不授予额外权限。窗口打开、HTTP 请求完成和个人已办不被当作整条流程结束、实际付款或已经记账。

## 真实测试入口

测试源码为 [ux-live-integration.spec.ts](../../apps/oa-web/e2e/ux-live-integration.spec.ts)，独立配置为 [playwright.ux-live.config.ts](../../apps/oa-web/playwright.ux-live.config.ts)。默认不运行，默认 E2E 排除此文件。专用私有配置位于项目 `.local/ux-live-integration.json`，可通过 `OA_UX_LIVE_CONFIG` 指定同一 `.local/` 内的其他文件；不接受仓库外配置或带凭据的 URL。

在 `apps/oa-web/` 执行：

```powershell
$env:OA_UX_LIVE_E2E = '1'
npx playwright test --config playwright.ux-live.config.ts
Remove-Item Env:OA_UX_LIVE_E2E
```

执行前须启动并核实独立测试平台，按[运行工具](../../deployment/dev/README.md)准备合成定义及两个不同的普通账号。旅程会真实新建申请、保存草稿并办理，不适用于公司业务库或原纷享销客。配置限定本机地址，关闭截图、trace 与视频；配置、测试输出及运行材料留在忽略目录，不写入密码、token 或原始认证响应。

## 未验收范围

本轮完成的是基本员工 OA 操作路径，尚未完成纷享销客业务的全量替换。客户与项目、合同关联、公司流水、实际收付、完整会计和正式报表、跨公司共享与核算权限、真实数据及附件迁移均需按[需求基线](../requirements/01-scope-and-requirements.md)逐项实施验收。应用页可展开的建设说明不提供这些业务的增删改查或核算能力。

合成表单验证不能代替所有旧表单、公式、复杂脚本、组织选择、子表、附件、退回重提和版本兼容验证；两个普通账号的任务归属也不能证明多公司隔离。生产身份策略、云部署、容量、消息与附件运行仍需专项验证。Android 保持另线。
