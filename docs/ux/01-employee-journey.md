# 员工旅程与 Web 交互改进基线

日期：2026-10-24，Asia/Shanghai。入口：[项目文档](../README.md)。查看 [交互旅程图](employee-journey.html)，编辑源为 [workflow v2 JSON](employee-journey.json)。

本文件与旅程图是**页面实施前的交互基线和本轮目标**，不是所有节点已经实现的声明。当前原生平台最小链路已通过真实验证，见 [运行报告](../verification/platform-runtime.md)；新 Web 仍需补齐员工从发起到追踪的操作入口，并修正登录页出现业务侧栏却无法进入业务的问题。实施与复测结果另行记录，不将本图替代验收。

基线保留实施前的观察和目标；本轮已实施内容及实际通过结果见[员工交互验证](../verification/web-interactions.md)。

## 1. 先解决入口承诺

实施前观察：[App.vue](../../apps/oa-web/src/App.vue) 在所有会话状态下渲染完整侧栏；[workspace.ts](../../apps/oa-web/src/state/workspace.ts) 的 `navigate` 将未登录的工作台／审批导航重定向回连接页。用户看到的是正常可点菜单，点击后却仍停在登录内容，界面没有兑现操作承诺。

本轮采用以下规则：

- 未登录时显示独立登录页、连接状态与必要的恢复操作，不渲染业务侧栏、任务数字或客户／财务快捷入口。
- 已登录后进入工作台，主导航围绕工作台、发起申请、审批与追踪展开；每个可点击入口都应产生页面、列表、表单或明确说明。
- 认证检测和登录中有明确状态；连接失败可重试，认证失败保留账号并清空密码；不把未登录、加载、无数据和失败混成同一个空白页。
- 退出成功回到独立登录页，并恢复连接与登录策略；退出失败保留当前会话并显示错误。会话失效清除旧记录后重新登录，不能保留上一账号的列表或详情。
- 演示必须由用户主动进入，并持续标明示例身份；演示状态不能执行真实发起或办理。

这些规则对应 REQ-007、REQ-008、REQ-009；公司权限仍由服务端实施，隐藏菜单不能代替授权。

## 2. 从 O2OA 原生交互借鉴的结构

下表是本仓库**原生源码观察**，不表示原生所有业务已在本轮浏览器逐项验收，也不直接决定公司的审批规则。

| 原生交互依据 | 本轮采用的员工体验 | 复用边界 |
| --- | --- | --- |
| [TaskCenter/Main.js](../../o2web/source/x_component_process_TaskCenter/Main.js) 的 `loadTab`、`showDraft`、`showMyCreated` 区分待办、已办、草稿与我创建的记录 | 使用任务视角组织列表，员工能分别处理、续填和追踪 | 各列表查询、计数、状态含义必须与真实 API 对应，不用同一份待办冒充所有标签 |
| [Application/Main.js](../../o2web/source/x_component_process_Application/Main.js) 的可发起流程加载及 `startProcessDraft` | 发起时先选当前身份可发起的流程，再进入填写 | 列表由平台授权筛选；不在前端臆造付款、报销等公司流程 |
| [Work/Main.js](../../o2web/source/x_component_process_Work/Main.js) 的工作／草稿／归档加载及表单运行 | 新 Web 提供可理解的摘要、入口和返回路径，动态表单与实际路由在原生运行页执行 | 不能用通用固定字段页面替代原生字段规则、条件或脚本；完整编辑与复杂组件兼容仍需逐项验证 |
| [Work/Main.js](../../o2web/source/x_component_process_Work/Main.js) 区分 `workId`、`workCompletedId` 与只读模式 | 追踪页明确显示在途、个人已办、整条流程终态 | 个人已办不自动标为整个流程办结；终态需要真实工作／归档证据 |

员工界面不展示 Java/JDBC、token、服务路径等实现内容。连接技术信息集中在连接诊断中，主流程只表达员工当前要做的事。

## 3. 四条主要旅程

| 场景 | 用户步骤 | 预期结果与返回路径 | 实施前状态 |
| --- | --- | --- | --- |
| 进入工作空间 | 打开系统 → 检测连接与会话 → 输入账号密码 → 工作台 | 会话有效直接进入；失败留在独立登录页，给出可执行的恢复操作 | 真实登录已接入，登录布局需调整 |
| 发起与续填 | 工作台 → 发起申请 → 选择授权流程 → 创建并进入原生表单；或草稿列表 → 续填 | 明确的用户点击才创建工作；创建中禁重复操作；返回后能找到自己的草稿或发起记录 | 新 Web 发起、草稿入口本轮补齐 |
| 处理事项 | 工作台／审批 → 待我处理 → 搜索与打开摘要 → 原生动态表单 → 按真实路由办理 | 回到新 Web 后可刷新并看到实际状态；成功处理后该条待办消失或进入下个环节 | 待办、已办、摘要、原生入口已有真实验证，需完善导航与刷新 |
| 追踪结果 | 我发起的／已办 → 记录 → 查看当前状态与原生详情 → 核对归档终态 | 区分当前环节、本人办理记录、整条流程结束；不伪造“已付款／已记账” | 个人已办已接入，我发起的与草稿视角本轮补齐 |

图中 11 个主节点表达交互目标，后续会计等建设范围放在结论卡中，避免把未实现业务画成可以进入的执行步骤。新 Web 本轮可落地的是入口、列表、真实流程目录、草稿／发起追踪与原生运行页衔接；完成状态应由实际实施和复测确认。

## 4. 页面与动作约束

| 页面／入口 | 必须提供的真实动作 | 加载、空态与失败行为 |
| --- | --- | --- |
| 独立登录页 | 检测连接、登录、必要时重试或进入明确演示 | 业务导航不存在；不支持的认证方式引导原平台；错误不会清空用户账号或暴露密码 |
| 工作台 | 待办、发起、草稿、我发起的等当前可用入口；当前身份与同步状态 | 数字未知显示未知／加载，不用 0 代替请求失败；没有权限的入口不作正常可点承诺 |
| 发起申请 | 加载可发起应用／流程；选择流程；显式创建并打开原生表单 | 无流程说明当前无可发起项目；请求失败允许重试；创建结果不确定时先核对已有草稿，不自动重复创建 |
| 审批与追踪 | 待我处理、我已处理、草稿、我发起的；每个标签独立查询、搜索、分页、刷新 | 标签切换重置页码；失败与无结果分开；保留当前标签、查询条件和可返回入口 |
| 事项摘要 | 打开正确工作或归档记录、进入对应原生页、关闭并返回列表 | 无权限明确提示并返回列表；原生地址未配置时给出说明；不构造携带 token 或自动办理 action 的 URL |
| 原生动态表单 | 按有效配置填写、保存草稿或选择办理路由 | 原生校验错误由原生页呈现；新 Web 不自行假定成功。返回或用户刷新时重新读取列表与状态 |
| 账户与连接 | 查看当前身份、明确退出、恢复连接 | 退出失败不伪造已退出；身份切换后所有旧列表、草稿、摘要与计数立即清理 |

在窄屏，使用可关闭的导航抽屉；选择页面后关闭抽屉。焦点可回到触发元素，抽屉／摘要可用 Escape 关闭。触摸区域、滚动和布局要实际检查，不只缩小桌面截图。

## 5. 失败、权限与恢复

旅程图合并了异常处理入口；具体行为按错误性质区分：

| 情况 | 用户提示与后续动作 | 不应发生 |
| --- | --- | --- |
| 连接失败／超时 | 说明连接未完成，留在当前入口；允许手动重试 | 自动进入演示、显示假 0 或假成功 |
| 登录失败 | 指出无法建立身份，保留账号，清空密码再试 | 出现业务侧栏或上一身份记录 |
| 会话失效（401） | 清空当前身份和业务数据，回独立登录页；重登后重新读取 | 旧响应覆盖新账号、继续展示旧详情 |
| 记录或操作无权限（403） | 保留会话；提示受限、返回列表，必要时联系管理员 | 伪装未登录、循环自动重试或仅靠隐藏按钮授权 |
| 校验失败／原生拒绝 | 原生页按实际字段或路由规则反馈；修正后由用户再次提交 | 新 Web 代填规则、静默跳过节点或自动选“同意” |
| 创建／办理结果不确定 | 明确“尚未确认”，先重新核对草稿、任务和流程状态，再决定下一步 | 盲目重放写请求导致重复工作、把 HTTP 200 直接写成办结 |

列表与详情、搜索、草稿和发起记录均按服务端当前身份授权。测试账号之间的任务可见性检查只证明对应场景，不能自动外推成多公司客户、资金、账簿隔离已验收。

## 6. 本轮不能伪装完成的范围

客户管理、项目协作、公司流水、财务报表与完整会计均保留在 [需求基线](../requirements/01-scope-and-requirements.md) 中。当前不能把几个统计卡或示例列表称为这些业务已实现。

- 客户／项目归属和共享规则、总部汇总口径按确认后的服务端授权设计；不从部门名猜公司。
- 付款审批、实际收付款、会计入账分别表达。审批通过不自动显示已付款、已记账。
- 凭证、科目、期间、结账、总账和正式会计报表仍是会计专项，不能用资金台账代替。
- 旧业务流程、132 个对象、60 条审批、历史附件与迁移关系仍需盘点和验收；本轮合成流程通过不代表已全部替换。
- 当前 Web 交互改进不承诺 Android、生产登录、云部署、性能及消息／附件完整验收。

未接入的业务应在建设说明中准确展示目标和状态，避免用不可点击的“正常菜单”或虚构数据制造已经具备能力的印象。
